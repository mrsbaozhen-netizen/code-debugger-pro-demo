1. Overview

Code Debugger Pro helps developers fix broken source code using LLM APIs. Paste code (and an optional error message), run Fix Code, and receive:

  • A short explanation of the bug
  • Corrected source in the Fixed tab
  • A line Diff view (removed / added lines)

No database or framework install — upload index.html and api.php to any PHP-capable host. API keys stay in the user's browser (localStorage).

3. Installation

Requirements

  • Browser: Chrome, Firefox, Safari, or Edge (recent version)
  • PHP proxy: PHP 7.4+, cURL extension, outbound HTTPS
  • Node proxy: Node.js 16+ (development only)
  • API key: From your chosen LLM provider (user-paid usage)

Shared hosting

  1. Upload all files to public_html or a subfolder.
  2. Place index.html and api.php in the same directory.
  3. Open https://yourdomain.com/path/index.html (not file://).
  4. Configure PHP Proxy (see Connection modes).

See INSTALL.txt for PHP built-in server and Node proxy commands.

4. Quick start

1. Provider → select vendor (e.g. DeepSeek)
2. Connection → PHP Proxy | Proxy URL → api.php
3. Click Test → green status dot
4. API Key → paste key → Save Configuration
5. Center panel → paste broken code → Fix Code
6. Right panel → Fixed / Diff → Copy or Download

Beside Proxy URL: green dot = proxy OK, red dot = failed (click link for setup guide). Use Test to check manually.

Reset defaults

Reset model & URL to defaults restores the built-in Model and Base URL for the current provider and clears wrong saved values.

Switching providers

Each provider remembers its own API key, model, and base URL. When you switch provider, the form loads that provider's saved settings (or defaults if none saved).

6.1 PHP proxy setup

  1. Upload api.php next to index.html.
  2. Connection: PHP Proxy, Proxy URL: api.php.
  3. Click Test — message: PHP proxy is reachable.
  4. Browser check: https://yoursite.com/api.php?ping=1 → {"ok":true,...}

Common errors: 404 (file missing), 500 (cURL disabled), opening app via file://.

6.2 Node proxy setup

  1. Terminal: node proxy/server.js (from package folder).
  2. Connection: Node Proxy.
  3. Proxy URL: http://localhost:8787/proxy (not api.php).
  4. Click Test — message: Node proxy is running.
  5. Check: http://localhost:8787/health

8. Custom provider

For private gateways, regional proxies, or any OpenAI-compatible API (/v1/chat/completions):

  1. Provider: Custom (OpenAI-compatible)
  2. Base URL — required, e.g. https://gateway.company.com/v1
  3. Model — required, your model identifier
  4. API Key — if your gateway requires it
  5. Use PHP Proxy — the hostname in Base URL is allowed automatically per request

To permanently whitelist hosts on the server, edit $extraAllowedHosts in api.php or EXTRA_ALLOWED_HOSTS in proxy/server.js.

11. FAQ

Failed to fetch?
Try PHP Proxy first (most reliable). Direct may work for DeepSeek/Groq but not for OpenAI/Claude/Gemini. Do not use file://.

DeepSeek with Direct works for me — do I need proxy?
No — if Direct works in your browser, you can keep it. Proxy is for users or networks where CORS blocks Direct, and for providers that never allow browser calls.

Wrong model/URL after switching provider?
Click Reset model & URL to defaults, then Save Configuration.

Direct works but proxy fails?
Check api.php?ping=1, PHP cURL, and that files are in the same folder.

Output cut off?
Advanced → Max tokens → 8192.

Database required?
No.

Embed in another site?
Host files and link or iframe; test X-Frame-Options on your host.

Is my API key sent to your server?
Keys go from the browser to the LLM API (via proxy if enabled). This package does not include a key storage backend.
